# Zenodo 发布步骤（仅供作者本人操作）

本轮没有注册账号、登录、建立存档、选择许可证或申请 DOI。仓库目前没有项目 LICENSE；公开可读不等于已授权任意复用。以下步骤需要作者本人完成，不是已经完成的事项。

1. 先确认作者姓名、顺序、单位、ORCID、通讯作者和发布权限，并决定项目软件许可证。第三方数据和出版社模板的权利不随软件许可改变；不要把模板、原始数据或私有逐点向量加入这个代码存档。
2. 核对 `submission-package/RELEASE/README.md` 与 `release-manifest.json`。拟上传文件为 `code-and-aggregate-results.zip`；核验 SHA-256 与本轮回执一致。它只含代码、协议、汇总和复现说明，不是完整原始数据包。
3. 作者本人登录 Zenodo，以软件/研究代码类资源建立草稿，填写真实作者元数据、研究题目、版本 `submission-2026-10`、摘要、关键词、相关 GitHub 分支和标签。不要使用占位作者发布。
4. 若平台提供预留 DOI，可在草稿阶段取得真实 DOI；先更新 `CITATION.cff`、主文和共享声明中的 DOI 占位，并重新构建两套稿件。预留 DOI 不等于已发布，投稿时如尚未公开应准确披露状态。
5. 上传 ZIP 与其清单，逐项核对许可、文件、访问条件和数据权利说明。作者确认接受平台条款后，再决定是否正式发布。不要选择会错误授权原始数据的许可。
6. 发布后实际打开 DOI，核对存档版本、文件 SHA、作者和许可证，再将正式 DOI 加入代码可用性声明。后续版本使用新版本记录，保留本次标签的可核验关系。

复现边界：代码和汇总可检查；完整金融复算仍需原始受限 FX、原 panel CSV 和原历史 Git 对象。不要把能够打开 ZIP 写成已经独立重现所有金融结果。已保存的 G4 是同一执行者在新克隆中的同数据数值复现。

待用户决定：真实作者与 ORCID、LICENSE、Zenodo 账号/DOI、是否发布以及访问条件。稿件中不填写未经核实的“无资金”“无冲突”或独家投稿保证。
